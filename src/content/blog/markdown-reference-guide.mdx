## Frontmatter

Every post begins with a YAML frontmatter block between `---` delimiters:

```yaml
---
title: "Your Post Title"
publishedAt: "2026-07-29"
updatedAt: "2026-07-29"
author: "Jules DiPrima"
summary: "A short description for previews and SEO."
image: "https://images.unsplash.com/photo-1455390582262-044cdead277a?w=800&h=192&fit=crop"
---
```

| Field | Required | Description |
|-------|----------|-------------|
| `title` | Yes | Post title displayed on the page and in listings |
| `publishedAt` | Yes | Publication date in `YYYY-MM-DD` format |
| `updatedAt` | No | Last revision date in `YYYY-MM-DD` format |
| `author` | No | Author name (defaults to site name) |
| `summary` | Yes | Short description used in meta tags and blog index cards |
| `image` | No | Hero image URL shown on the post page and in social share cards |

## Headings

Use `#` through `######` for heading levels.

```markdown
# Heading 1 — Page Title
## Heading 2 — Section
### Heading 3 — Subsection
#### Heading 4 — Group
##### Heading 5 — Subgroup
###### Heading 6 — Label
```

## Heading 2 — Section

### Heading 3 — Subsection

#### Heading 4 — Group

##### Heading 5 — Subgroup

###### Heading 6 — Label

## Text Formatting

| Style | Syntax | Example |
|-------|--------|---------|
| Bold | `**text**` or `__text__` | **NIST SP 800-53 Rev. 5** |
| Italic | `*text*` or `_text_` | *Continuous Authorization to Operate* |
| Bold + Italic | `***text***` | ***FedRAMP Moderate Baseline*** |
| Strikethrough | `~~text~~` | ~~legacy ATO process~~ |
| Inline code | `` `code` `` | `POA&M` |
| Link | `[text](url)` | [NIST CSF](https://www.nist.gov/cyberframework) |

## Blockquotes

Use `>` for blockquotes, including nested ones:

```markdown
> The POA&M must be reviewed and updated within 30 days of any significant change to the system boundary.
>
> > This includes changes to network architecture, data flows, and interconnected systems.
>
> Evidence of review must be maintained for audit purposes.
```

>
> > This includes changes to network architecture, data flows, and interconnected systems.
>

## GRC Project Management Example

Below is a sample RACI matrix for a cATO implementation project:

| Task | PM | RMF SME | Security Engineer | Authorizing Official |
|------|----|---------|-------------------|---------------------|
| Define system boundary | A | R | C | I |
| Select controls | C | R | C | I |
| Implement control CM-2 | I | C | R | I |
| Conduct assessment | C | C | R | A |
| Draft authorization letter | C | C | I | R |
| Continuous monitoring | I | A | R | I |

- **R** = Responsible (does the work)
- **A** = Accountable (signs off)
- **C** = Consulted (provides input)
- **I** = Informed (kept up to date)

```html

- **Week 2–3:** Control selection and tailoring
- **Week 4–6:** Implementation and evidence collection
- **Week 7–8:** Assessment and remediation
- **Week 9:** Authorization package submission

</details>
```
